# Prompt: Restore Google AI provider (analysis + embeddings)

## Goal

Reverse the OpenRouter swap (`prompts/openrouter-swap.md`) and move both the
analysis call and the embedding call back to the direct Google provider
(`@ai-sdk/google` + `GOOGLE_GENERATIVE_AI_API_KEY`).

- Analysis: `gemini-2.5-flash` via `@ai-sdk/google`
- Embeddings: `gemini-embedding-001` at 1536 dims via `@ai-sdk/google`

Because OpenRouter's `text-embedding-3-small` and Google's `gemini-embedding-001`
produce vectors in different spaces, any embeddings already stored must be
nulled out so the backfill path re-generates them with Google on the next
`POST /api/analyze` run. The exact SQL is provided in the manual test steps.

`@openrouter/ai-sdk-provider` stays in `package.json` (user's choice) but is
no longer used by the AI layer.

  `node_modules/@ai-sdk/google/docs/` for the installed version before writing

  Change to `"gemini-embedding-001"`. `EMBEDDING_DIMENSIONS` stays 1536.
- `.env.example` — has `OPENROUTER_API_KEY`. Add `GOOGLE_GENERATIVE_AI_API_KEY`;
  keep `OPENROUTER_API_KEY` (package stays installed).
- `AGENTS.md` §21 env table — update the AI key row to `GOOGLE_GENERATIVE_AI_API_KEY`
  and update model names to `gemini-2.5-flash` + `gemini-embedding-001`.

## Decisions / assumptions

1. **Install:** `pnpm add @ai-sdk/google`. Do not remove `@openrouter/ai-sdk-provider`.
2. **Provider module:** `lib/ai/provider.ts` becomes the single place the Google
   provider is instantiated. Read `GOOGLE_GENERATIVE_AI_API_KEY` here only.
   Keep `import "server-only"`. Verify the exact factory/export from bundled docs.
3. **Analysis model:** `"gemini-2.5-flash"` (no OpenRouter namespace prefix).
   Verify the exact model ID string from bundled docs — do not use from memory.
4. **Embedding model:** `"gemini-embedding-001"` with `outputDimensionality: 1536`
   (matches the `vector(1536)` column). Verify the exact `providerOptions` key
   from bundled docs.
5. **Dimension assertion** in `embed.ts` stays — still asserts `embedding.length === 1536`.
6. **Re-embed SQL:** existing embeddings were generated by OpenRouter's
   `text-embedding-3-small` and are incompatible with Google's space. Provide
   `UPDATE article_analyses SET embedding = NULL;` for the user to run in the
   Supabase SQL Editor before the next analysis run. The LEFT-JOIN backfill path
   already handles rows whose analysis row exists but `embedding IS NULL`.
7. **No other logic changes:** Zod schema, normalization, bias derivation, retry,
   batching, orchestration, queries, route handler, DB schema, index, and
   `match_articles` RPC are all unchanged.

## Manual test steps (§17)

Preconditions: set `GOOGLE_GENERATIVE_AI_API_KEY` in `.env.local`. Have scraped
articles present. Watch the `pnpm run dev` terminal for analysis logs.

1. **Null out old embeddings** (incompatible vector space) in Supabase SQL Editor:
   ```sql
   UPDATE article_analyses SET embedding = NULL;
   ```
2. Analyze all pending (backfill re-embeds existing rows + analyzes new ones):
   ```bash
   curl -X POST http://localhost:3000/api/analyze \
     -H "x-skeem-admin-secret: $SKEEM_ADMIN_SECRET"
   ```
   Expect a summary object with `analyzed` and/or `embeddingsBackfilled` counts.
3. Auth rejection (expect `401`):
   ```bash
   curl -i -X POST http://localhost:3000/api/analyze
   ```
4. UI: open a news detail page for an analyzed article — full analysis renders,
   and Related Stories appears once ≥2 articles have Google embeddings.
